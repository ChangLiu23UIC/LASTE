# Photobleaching Proteomics — Zebrafish Olfactory Epithelium and Spinal Cord

Label-free proteomics comparing photobleached (PB) and non-photobleached (NPB) cell
fractions in *Danio rerio*, in two tissues:

| Tissue | Samples | Data |
|---|---|---|
| **OE** — olfactory epithelium | 17 runs, two batches (`OE1`, `OE2`) | `data/oe_proteomics/` |
| **SC** — spinal cord | 4 runs, one batch, no replicates | `data/spinal_cord_proteomics/` |

Proteins are quantified as NSAF (normalised spectral abundance factor) from FragPipe
spectral counts, restricted to *Danio rerio* entries. The pipeline then produces sample
correlation, a UMAP embedding with Leiden grouping, clustered heatmaps, and GO enrichment.

## Quickstart

```bash
python -m venv .venv
.venv/Scripts/activate          # Windows;  source .venv/bin/activate on Unix
pip install -r requirements.txt

python src/oe_analysis.py       # -> results/oe/{figures,tables}/
python src/spine_analysis.py    # -> results/spinal_cord/{figures,tables}/
```

Two commands regenerate every committed figure and table. Both scripts resolve their paths
through `src/paths.py`, so they run from any working directory.

## Sample naming

Format: `{tissue}{batch}_{treatment}_{fraction}_R{replicate}` — e.g. `OE1_PB_neg_R2`.

| Token | Meaning |
|---|---|
| `OE1` / `OE2` | olfactory epithelium batch 1 (`1-27-*` files) / batch 2 (`5-22-*` files) |
| `SC` | spinal cord (single batch) |
| `PB` | photobleached |
| `NPB` | non-photobleached control — raw filenames use the legacy prefix `BY` |
| `pos` / `neg` | sorted fractions: non-bleached cells / cells the photobleached signal shifts into |
| `R1`–`R3` | replicate |

The raw-filename → sample-label map is `FILE_MAPPING` at the top of each script.

## The UMAP panel

`src/oe_analysis.py` deliberately does **not** draw a UMAP, so rerunning the pipeline leaves
the published panel intact. `UMAP_OE.*` was generated by `src/umap_tuning.py` with:

```bash
python src/umap_tuning.py --n_neighbors 3 --min_dist 0.1 --metric correlation \
    --leiden_resolution 4.0 --leiden_neighbors 3 --random_state 12 \
    --repulsion_strength 3.05 --spread 2.1
```

`src/umap_tuning_large.py` takes the same arguments and wrote `UMAP_OE_large.*`.

`src/spine_analysis.py` does draw the SC UMAP itself, from a pinned embedding (below).

## Pinned outputs

Two steps are not reproducible on their own, so the published answer is stored in `results/`
and reused. **Delete the file to recompute that step from scratch.**

| File | Why it is pinned |
|---|---|
| `results/spinal_cord/tables/UMAP_SC_embedding.csv` | UMAP on 4 points with `n_neighbors=2` is degenerate. Fresh processes settle on one of ~3 different layouts; `random_state`, `np.random.seed`, `NUMBA_NUM_THREADS=1` and `PYTHONHASHSEED` all fail to fix it. The 17-sample OE embedding *is* bit-for-bit reproducible — this affects SC only. |
| `results/*/tables/GO_Enrichment_*_table.csv` | g:Profiler is a live service and its annotation database moves — the same query returned 207 OE terms in May 2026 and 203 today. The figures are drawn from the stored tables, so a rerun needs no network. |
